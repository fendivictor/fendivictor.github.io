API Authentication di Laravel: Sanctum, Passport, atau JWT?

Setiap project Laravel yang butuh API punya pertanyaan yang sama — pakai apa untuk authentication? Ini jawabannya, berdasarkan pengalaman production, bukan dokumentasi teoritis.

Laravel API Sanctum Authentication

Pertanyaan paling sering muncul di forum Laravel, Discord, dan obrolan developer: "Gue mau bikin API, pakai Sanctum, Passport, atau JWT?" Jawaban default kebanyakan orang: "Sanctum." Tapi jawaban yang benar adalah: "Tergantung."

Masalahnya Bukan "Yang Mana Lebih Bagus"

Ketiga opsi ini punya use case masing-masing. Masalahnya, kebanyakan developer memilih berdasarkan hype thread di Twitter atau rekomendasi chat GPT, bukan berdasarkan kebutuhan project mereka. Akibatnya? Over-engineering di satu sisi, under-engineering di sisi lain.

Mari kita bedah satu per satu — tanpa bias, dengan perspektif orang yang sudah pakai ketiganya di production.

Laravel Sanctum

Sanctum adalah paket authentication bawaan Laravel yang menangani dua skenario berbeda:

1. SPA Authentication (Cookie-based)

Kamu punya frontend (React, Vue, Inertia) yang hidup di domain yang sama dengan backend Laravel. Sanctum menangani authentication lewat cookie — sederhana, aman, tanpa ribet token management.

// routes/api.php
Route::middleware('auth:sanctum')->get('/user', function (Request $request) {
    return $request->user();
});

// Login dari SPA
await axios.post('/login', { email, password });
// Cookie otomatis diset — selesai.

2. API Token Authentication

Untuk API yang dipanggil dari client pihak ketiga — mobile app, atau integrasi eksternal. Setiap user bisa punya multiple token dengan scope tertentu.

// Membuat token untuk user
$token = $user->createToken('mobile-app', ['read', 'write']);

// Menggunakan token
$response = Http::withToken($token->plainTextToken)
    ->get('https://api.example.com/me');

Kapan pakai Sanctum? SPA dengan Laravel backend, simple API untuk mobile app, atau microservice yang butuh authentication cepat tanpa setup rumit.

Kelebihan Sanctum

  • Setup minimalis — composer require laravel/sanctum, migrate, selesai
  • Bawaan Laravel — maintained by Laravel team, selalu kompatibel dengan versi terbaru
  • Cookie-based SPA auth — paling aman untuk same-origin frontend
  • Token management — revoke, scope, dan expiration built-in
  • Database optional — bisa pakai file-based token untuk simple API

Kekurangan Sanctum

  • Bukan OAuth2 — tidak support authorization flow penuh (seperti "Login with Google")
  • Token stored di database — setiap request hit database untuk validasi token
  • Tidak stateless — untuk SPA auth, tetap perlu session/database
  • Scope system terbatas — tidak se-flexible Passport

Laravel Passport

Passport adalah implementasi penuh OAuth2 server untuk Laravel. Kalau kamu butuh fitur OAuth2 yang lengkap — authorization codes, client credentials, implicit grants, refresh tokens — ini tool-nya.

// Authorization Code Grant (full OAuth2 flow)
Route::middleware('auth:api')->get('/user', function (Request $request) {
    return $request->user();
});

// Passport menyediakan endpoint OAuth2 lengkap:
// /oauth/authorize
// /oauth/token
// /oauth/tokens
// /oauth/clients
// /oauth/personal-access-tokens

Kapan pakai Passport? Kalau kamu benar-benar butuh OAuth2 — misalnya, membangun API publik yang memungkinkan developer pihak ketiga membuat aplikasi di atas platform-mu. Contoh nyata: Laravel Forge, Laravel Vapor.

Kelebihan Passport

  • OAuth2 compliant — implementasi standar lengkap
  • Authorization Code Grant — flow teraman untuk third-party apps
  • Refresh tokens — token bisa di-refresh tanpa user login ulang
  • Client management — dashboard untuk manage OAuth clients
  • Scope system powerful — kontrol akses granular

Kekurangan Passport

  • Setup berat — banyak migration, config, dan dependency
  • Overkill untuk kebanyakan project — 90% API gak butuh OAuth2 penuh
  • Performance overhead — lebih banyak database query per request
  • Complexity — OAuth2 itu protocol yang rumit, banyak edge case
  • Maintenance concern — beberapa developer merasa Passport kurang diminati Laravel team belakangan ini dibanding Sanctum

JWT (tymon/jwt-auth)

JWT (JSON Web Token) adalah standar yang bukan bawaan Laravel — diimplementasikan lewat package tymon/jwt-auth. JWT bersifat stateless: token berisi semua informasi user, di-encode dan di-sign server-side, dan divalidasi tanpa perlu database lookup.

// Generate token
$token = JWTAuth::attempt($credentials);

// Menggunakan token
$response = Http::withToken($token)
    ->get('https://api.example.com/me');

// Di middleware, JWT di-decode tanpa hit database:
// 1. Ambil token dari header
// 2. Verifikasi signature
// 3. Decode payload
// 4. Done — tidak ada database query

Kapan pakai JWT? Microservices yang butuh stateless auth, mobile app dengan performa kritis, atau arsitektur di mana setiap service harus validasi token secara independen tanpa shared database.

Kelebihan JWT

  • Stateless — tidak ada database query untuk validasi token
  • Performa tinggi — ideal untuk high-traffic API
  • Cross-service compatible — service lain bisa validasi token tanpa akses ke user database
  • Self-contained — token berisi semua info yang diperlukan

Kekurangan JWT

  • Tidak bisa di-revoke dengan mudah — token valid sampai expired, kecuali pakai blacklist (yang bikin jadi stateful lagi)
  • Token size besar — dibanding simple API token, JWT payload bisa lumayan besar
  • Package third-party — bukan official Laravel package, kadang telat update
  • Security pitfalls — salah konfigurasi bisa berakibat fatal (weak secret, no rotation, dll)
  • Refresh token complexity — harus implement sendiri atau pakai library tambahan

Perbandingan Head-to-Head

Setup Complexity

Sanctum: ⭐ — Hampir zero-config. Install, migrate, publish config (optional), pakai.

JWT: ⭐⭐ — Config secret key, auth provider, middleware. Lumayan setup tapi masih manageable.

Passport: ⭐⭐⭐⭐ — Banyak migration, encryption keys, client setup, dan konfigurasi OAuth2.

Performance

JWT: 🏆 — Stateless, tidak ada DB query. Cocok untuk high-traffic.

Sanctum: 🥈 — Token validasi via DB, tapi query-nya simpel dan bisa di-cache.

Passport: 🥉 — Paling banyak DB query per request (token + client validation).

Security

Passport: 🏆 — OAuth2 standar industry, authorization code grant paling aman.

Sanctum: 🥈 — Cookie-based SPA auth secure untuk same-origin. Token auth good enough untuk kebanyakan case.

JWT: 🥉 — Secure kalau diimplementasi dengan benar. Tapi banyak developer yang salah konfigurasi.

Flexibility

Passport: 🏆 — OAuth2 penuh, scope, refresh token, authorization code.

JWT: 🥈 — Stateless, cross-service, customizable payload.

Sanctum: 🥉 — Scope terbatas, tidak OAuth2 compliant, tapi cukup untuk kebanyakan case.

Maintenance & Future-proof

Sanctum: 🏆 — Official Laravel package, selalu di-maintain bareng Laravel core.

Passport: 🥈 — Official package tapi ada tanda-tanda Laravel mendorong Sanctum untuk kebanyakan use case.

JWT: 🥉 — Third-party package, risiko telat update atau abandon.

Decision Framework: Pilih yang Mana?

Biar gak bingung, ini flowchart sederhana yang aku pakai:

  1. Apakah kamu membangun API publik untuk developer pihak ketiga?
    • Ya → Passport. Kamu butuh OAuth2 yang sesungguhnya.
    • Tidak → lanjut ke pertanyaan berikutnya.
  2. Apakah arsitekturnya microservices tanpa shared database?
    • Ya → JWT. Stateless auth adalah keharusan.
    • Tidak → lanjut ke pertanyaan berikutnya.
  3. Apakah frontend-mu SPA yang di-serve dari domain yang sama?
    • Ya → Sanctum (SPA mode). Ini use case paling idealnya.
    • Tidak → Sanctum (token mode).

Intinya: Kalau kamu ragu, pake Sanctum. Itu default yang benar untuk 80% project. Passport dan JWT punya tempatnya masing-masing, tapi jangan dipakai "karena keren" — pakai karena memang dibutuhkan.

Tips dari Production

1. Token Expiration Jangan Terlalu Lama

Sering lihat developer set token lifetime sampai 10 tahun "biar gak ribet." Jangan. Set 1-2 jam untuk access token, dan implement refresh token kalau dibutuhkan. Kalau pakai Sanctum token mode, set expiration di config.

// config/sanctum.php
'expiration' => 120, // menit — 2 jam

// Untuk SPA cookie auth
'session_lifetime' => 120,

2. Pakai Scope untuk API yang Bisa Diakses Publik

Kalau API-mu bisa diakses oleh third-party (sanctum token mode), gunakan scope untuk membatasi akses. Jangan kasih full access ke semua endpoint.

// Membuat token dengan scope terbatas
$token = $user->createToken('partner-integration', ['orders:read', 'products:read']);

// Di route
Route::get('/orders', [OrderController::class, 'index'])
    ->middleware(['auth:sanctum', 'scope:orders:read']);

3. Logout = Revoke Token

Untuk Sanctum dan Passport, pastikan logout benar-benar menghapus atau revoke token. Token yang valid tapi tidak dipakai adalah security risk.

// Sanctum: revoke current token
$request->user()->currentAccessToken()->delete();

// Revoke semua token (force logout everywhere)
$request->user()->tokens()->delete();

4. Rate Limiting di Endpoint Auth

Endpoint login dan token refresh jadi target brute force. Selalu pakai rate limiting.

Route::post('/login', [AuthController::class, 'login'])
    ->middleware('throttle:5,1'); // 5 request per menit

5. Jangan Simpan Token di LocalStorage (SPA)

Kalau pakai Sanctum SPA mode, biar Laravel yang handle cookie-nya. Jangan simpan token di localStorage — rentan XSS. Sanctum SPA auth menggunakan cookie yang secure dan httpOnly secara default.

Ketika Semuanya "Salah"

Terkadang, jawabannya bukan ketiga opsi di atas. Beberapa skenario di mana kamu perlu alternatif:

  • SSO (Single Sign-On) — pakai Laravel Socialite + session management, bukan Sanctum/Passport/JWT.
  • API Gateway pattern — pakai API Gateway (Kong, Traefik) yang handle authentication, dan Laravel hanya validate downstream token.
  • Legacy system integration — kadang harus ikut standar yang sudah ada (Basic Auth, API Key, HMAC).
  • Real-time WebSocket auth — Sanctum bisa, tapi pertimbangkan juga Gateway-level auth untuk WebSocket connections.

Kesimpulan

Setelah pakai ketiganya di berbagai project, ini rekomendasi praktis aku:

  • Default choice: Sanctum — simple, resmi, dan cukup untuk 80% kasus.
  • Public API platform: Passport — kalau kamu benar-benar butuh OAuth2.
  • Microservices / high-performance: JWT — tapi dengan resiko maintenance yang harus dipertimbangkan.

Jangan pilih authentication package berdasarkan jumlah star di GitHub atau thread viral di Twitter. Pilih berdasarkan arsitektur project-mu, tim-mu, dan kemampuan maintenance-mu ke depan.

Yang paling penting: implementasi yang benar dari package yang sederhana jauh lebih baik daripada implementasi yang buruk dari package yang canggih.

TL;DR: Default ke Sanctum. Pakai Passport kalau butuh OAuth2 sesungguhnya. Pakai JWT kalau arsitekturnya microservices stateless. Dan apapun yang kamu pilih, pastikan implementasi security-nya benar — bukan cuma asal jalan.
